\begin{abstract}

Business rules play a central role in enterprise applications, as they capture organizational policies, legal requirements, and decision logic that guide business processes. In legacy systems, however, these rules are often embedded in poorly documented source code, spread across different parts of the system, and mixed with technical implementation details. As a result, when a business rule changes, developers must identify the parts of the code that implement it before making the necessary modifications. This task can be time-consuming and error-prone, particularly in large and complex codebases.

In this paper, we present a fully automated approach to assist developers in locating the code that may need to be modified when a business rule changes. The approach aims to reduce the search space by identifying candidate methods that are likely to implement the affected rule. Given a textual description of a business rule, our approach uses embeddings to identify its relationship with the source code and combines this analysis with source code analysis to filter the methods and retain those that are most relevant to the rule. We evaluate the approach on a real-world industrial codebase and show that it can effectively narrow down the set of candidate methods, providing useful support for developers during software maintenance and evolution tasks.

\end{abstract}
